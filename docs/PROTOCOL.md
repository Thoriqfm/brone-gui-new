# PROTOCOL

v0.1 message: SET_EXPRESSION; request_id string; payload with emotion, intensity (0..1), transition_ms. More message types are planned.

MQTT additionally accepts the brone-talk ingress format `{"expression":"happy","duration":4}` on the expression topic. The backend validates and translates it into a complete v0.1 command with a generated request ID. Mappings: neutral -> idle, excited -> happier, confused -> thinking; speaking restores the last brone-talk answer emotion (initially idle). Canonical emotion names are also accepted. Duration is optional, finite, nonnegative seconds counted from backend MQTT receipt, including queue time; when supplied, it schedules idle (zero means immediate). Missing duration holds until another applied command. Each applied HTTP/MQTT expression or mapped stage cancels/replaces the prior timer; invalid/ignored telemetry does not. Duration is not transition_ms; adapter transitions use 700 ms and intensity 1. The idle command starts its normal transition at expiry, rather than guaranteeing a fully settled idle at that instant.

On `robot/voice_stage`, stage=llm/state=start selects thinking; stage=error/state=llm selects timeout. Stage/state must be nonempty strings; additional telemetry metadata is ignored. Other valid stage/state pairs do not change the face or its timer. Stage thinking/timeout do not replace the stored answer emotion; an explicit confused answer does. No turn ID correlation or audio completion detection exists. HTTP accepts only its existing envelope; shared schema and browser messages remain unchanged.

MQTT ingress accepts the same request envelope and defaults as HTTP, on `robot/expression` by default. Enabled by default; configure `BRONE_MQTT_BROKER` and `BRONE_MQTT_PORT` (defaults `localhost:1883`). Set `BRONE_MQTT_ENABLED=false` for HTTP-only operation. Legacy `BRONE_MQTT_HOST` is accepted when `BRONE_MQTT_BROKER` is absent. Invalid input, retained replay, and payloads above 16 KiB are rejected without changing state. The subscription uses QoS 1, a clean session, reconnect/resubscribe and a bounded 64-command backlog; overload drops new messages with a warning. No MQTT application acknowledgment, persistent offline queue, exactly-once guarantee or request-ID deduplication is provided. HTTP remains available during migration; both ingress paths update the same state. Canonical WebSocket/shared schema is unchanged. See [MQTT setup](MQTT.md).

Local ingress: `POST /api/face/expression` accepts exactly this envelope; invalid JSON or fields return 422. Success returns 200 with `status: accepted`, `request_id`, and `connected_clients` (not a frontend display acknowledgment). `GET /api/face/state` returns the latest accepted command. `/ws/face` sends the latest state on connect and subsequent commands to all connected displays; it no longer cycles demo expressions. State is held in one process and resets to idle on restart. Browser origins are limited to localhost/127.0.0.1 ports 5173 (frontend) and 8000 (Swagger UI). Run on loopback only; remote access requires authentication. See [local demo](LOCAL_LLM_DEMO.md).

Finalized expressions: idle, happy, happier, sad, cry, shock, thinking, timeout. The shy expression is intentionally excluded from the finalized design and is rejected, without an idle fallback. happier-transition is a frontend-only intermediate pose before happier, not a protocol emotion. The semantic state remains happier throughout this visual sequence.

HTTP input defaults: `POST /api/face/expression` requires `type`, `request_id`, and `payload.emotion`. Omitted `payload.intensity` defaults to `1`; omitted `payload.transition_ms` defaults to `700`. Explicit valid values override either default, including zero. Nulls and invalid values still return 422. The HTTP request schema is generated in FastAPI OpenAPI (`ExpressionRequest`); [minimal input example](../shared/examples/expression-request.json). The backend normalizes this input into a complete v0.1 command before storing or broadcasting it. Shared JSON schema, frontend parser, and Python `ExpressionMessage` continue to require both fields on WebSocket messages and GET state responses.

`timeout` represents an unavailable or nonresponding LLM. Send it through the existing `SET_EXPRESSION` command. Both renderers morph eyes and mouth into and out of timeout, retaining the original SVGs at rest. Eyes route through Idle when needed; the mouth morphs directly. Spiral rotation runs in opposing directions (one turn per 2.4 seconds), resumes at the end of entry, and carries its visible angle into the exit morph. Timeout morphs suspend blinking. Reduced-motion preference disables rotation and makes transitions immediate. Manual preview: key 8 or the timeout control. No LLM health detection or automatic timeout trigger exists yet; the command producer must select timeout and a recovery expression explicitly.
